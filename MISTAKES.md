# EigoSage Mistakes

## Lessons Learned

- **S-358: Gemini thinking tokens can silently truncate output** (2026-06-01) — When upgrading to Gemini 3.5 Flash (which enables thinking by default), output was being silently truncated. Fix: explicitly set `thinkingBudget: 0` on all REST API call sites. Always check model defaults when upgrading.
- **OcrTextMerger word-to-box misalignment** (pre-v0.8.0) — Early merge strategy tried to align words even when ML Kit and Gemini had different word counts per line. This caused taps to look up the wrong word. Fix: only replace text when word counts match exactly; otherwise keep ML Kit's original text.
- **kotlinx.serialization `JsonArrayBuilder.add()` has no String overload** (2026-09-04) — Unlike `JsonObjectBuilder.put("key", "value")` which accepts raw strings, `putJsonArray("x") { add("literal") }` fails to compile ("actual type String, expected JsonElement"). Must wrap: `add(JsonPrimitive("literal"))`. Caught building GeminiLiveClient's setup message (`responseModalities`).
- **Ktor's Android engine (`ktor-client-android`) has no WebSocket support** — the `WebSockets` plugin requires CIO, Java, or OkHttp. Don't add `install(WebSockets)` to the shared REST `HttpClient` in AiModule; give the Live client its own OkHttp-based client instead.
- **An app rename must be grepped for in string literals used as cross-app protocol values, not just class/file names** (2026-09-06) — "Send to EigoQuest" shipped, worked, then EigoJourney's app name changed and only the UI-facing class names got left alone while the actual `target_app: "eigoquest"` payload value silently stopped matching the receiver's filter. The feature kept "succeeding" (row inserted) while doing nothing. A rename needs a full-repo grep for the OLD name including runtime string values, not just symbols the compiler would catch.
- **A root cause can hide BEHIND a fix that looked complete** (2026-10-11) — The "Send to EigoJourney" rename fix (above) made the feature "ship," but the real reason it never worked was one layer deeper: `JCoinModule.JCOIN_SUPABASE_URL` pointed at an old Supabase project that had gone NXDOMAIN, so the write could never reach any server at all, regardless of `target_app`. A fix that addresses a confirmed bug is not proof the feature now works — "it compiles and the logic is right" still isn't "it can reach the network it needs."
- **"The secret is corrupted" was an inference I wrote down as a diagnosis** (2026-09-25, corrected 2026-10-16) — the CI error looked like a malformed keystore, so I called the `KEYSTORE_BASE64` secret corrupted and asked Jay a question built on that. One `gh secret list` (names only) would have shown the secret never existed. Check that the input exists before diagnosing what is wrong with it. **Repeated 2026-10-17 (BUG-005):** I wrote that the app sent a stale J Coin app key; jayhub:110 found the server-side `APP_KEY_EIGOSAGE` was never set at all. Same shape twice: a 401/parse error on a credential means "check it exists on both ends" first, not "the value is wrong".
- **Stale `.git/index.lock` recurs in this repo after session churn** (5 times, 2026-07 to 2026-10) — account switches kill git processes mid-operation. Check age + `fuser .git/index.lock`; a 0-byte lock with no holder and an old mtime is safe to remove. Don't re-diagnose from scratch each time.
- **Kotlin block comments nest, so a literal `/*` inside KDoc prose (even inside backticks) opens an unterminated nested comment** (2026-10-11) — writing `` `/functions/v1/*` `` inside a `/** ... */` doc comment swallowed the rest of the file as a comment ("Unclosed comment" reported at EOF), which then cascaded into an unrelated-looking KSP error on every class injecting the now-uncompilable type. When a KSP/Hilt error blames `error.NonExistentClass` on some other constructor, check whether a sibling file actually failed to compile first — don't debug the symptom file.
